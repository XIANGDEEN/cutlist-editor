# 把「剪映 11.5 那条路」的模式拆开，再看我们抄了什么

这份文档不是讲怎么用剪映，而是记录我们从
[`jjjane233/jianying-editor-skill-11.5`](https://github.com/jjjane233/jianying-editor-skill-11.5)
（`isYangs/jianying-editor-skill` 的 11.5 适配分支）身上拆出来的**工程模式**，
以及每条模式在 `cutlist-editor` 里落成了什么、还差什么。

先给结论：**值得抄的不是它的功能，是它的边界感。**
它明确知道自己只能做到「产出一份剪映能打开的草稿」，剩下三步（打开检查、微调、导出）
全部交还给人，而且把这三步写进 README 和验收记录里。我们上一版框架的毛病恰恰相反——
什么都想自动，结果在最贵的那一步（素材/导出）上撞墙。

---

## 一、它的八个模式

| # | 模式 | 它怎么做 | 为什么有效 |
|---|---|---|---|
| 1 | **写数据，不点鼠标** | 只写草稿文件，不做 GUI 自动化 | GUI 自动化的断点太多（窗口位置、DPI、语言、弹窗、版本），写文件只有 schema 一个断点 |
| 2 | **借官方编解码，不逆加密** | 调用本机 `videoeditor.dll` 的 DraftIO 做 encode/decode | 不碰破解、不碰安装文件，剪映升级只会让"版本号不匹配"，不会让"格式全错" |
| 3 | **写后回读自检** | 写完立刻重新读出草稿，比对关键字段；再登记首页 `draft_ids` | 写成功 ≠ 剪映能打开；回读是唯一低成本的"它真的活了吗" |
| 4 | **分阶段接手** | AI 出草稿 → **人**打开确认 → **人**点导出 | 把"必须人做"的那一步显式放在协议里，而不是假装能自动化 |
| 5 | **规则归规则，语义归 AI** | 它那套 `cut --prompt` 只解析"竖屏/每段3秒/引号里的文字"，**不判断画面内容** | 规则解析要确定性、可回归；语义判断才交给模型。混在一起就两头不靠 |
| 6 | **运行时取签名** | 官方素材库（音乐/贴纸/滤镜/音效）在运行时取签名，不用过期直链 | 直链会死，签名会变；把"取资源"变成一次调用而不是一份快照 |
| 7 | **画质克制** | `--quality auto` 只在需要时启用超分，且明说会传云端、烧点数 | 高成本操作不默认开、不隐藏成本 |
| 8 | **版本钉死 + 预检** | `VERIFIED_VERSION = 11.5.0.14471`，`preflight.py` 先查 DLL 在不在、依赖全不全 | 与其运行时炸在半个小时后，不如启动时 3 秒说"不行，因为 X" |

它自己承认的边界（我们照抄进验收表）：不支持 GUI 实时操作、不支持人机同时编辑同一草稿、
不提供剪映原生全保真导出、只验证单一版本、超分要联网。

## 二、映射到我们的框架

| 模式 | `cutlist-editor` 里的落点 | 状态 |
|---|---|---|
| 1 写数据不点鼠标 | 我们的"数据"是**剪辑单 + ffmpeg 命令**，全程不驱动任何 GUI | ✅ 原生如此 |
| 2 借官方编解码 | 我们**不碰**剪映草稿：需要剪映草稿时，把剪辑单导出成它的 `spec.json` 交给有 DLL 的工具（`scripts/export_jianying_spec.py`） | ✅ 已落地（lossy，落差写进 `.notes.md`） |
| 3 写后回读自检 | 每镜先写 `clip.part.mp4`，ffmpeg 干净退出才 `os.replace` 成 `clip.mp4`；成片再 `ffprobe` 回读尺寸/时长写进 `report.json` | ✅ 已落地 |
| 4 分阶段接手 | 五步工作流写明：预检 → 回读 → 出片 → **验收交人**；不假装能替你判断"好不好看" | ✅ 已落地（文档层） |
| 5 规则归规则 | `check_cutlist.py` 只做确定性解析/校验；"选哪个片段、讲什么故事"由人和模型决定，脚本不猜 | ✅ 已落地 |
| 6 运行时取签名 | 我们无云素材；等价物是**音效按需合成**（`gen_sfx.py`，缺哪个现造哪个，不预置一堆） | ✅ 已落地 |
| 7 画质克制 | `--preview` 用 veryfast/crf28；正式才 medium/crf19；源分辨率不足时**明确标 `upscale` 降级**而不是悄悄放大 | ✅ 已落地 |
| 8 版本钉死 + 预检 | `scripts/preflight.py`：Python/ffmpeg/四个滤镜/中文字体/磁盘/剪辑单，一次跑完；ffmpeg 缺 `xfade`/`fadewhite` 时**降级不崩** | ✅ 已落地 |

还差的（明说，不装）：

- **没有** `draft_ids` 那种"写进剪映首页"的登记——那是草稿工具的事，不是我们的。
- **没有**真实的剪映 11.5 端到端验证——沙箱装不了依赖（pip 出网 reset），必须在你机器上跑。
- **没有**自动导出剪映成品——这是剪映 7+ 的硬限制（上游 5.9 之外全废），不要试图绕过。

## 三、接线：我们的剪辑单 → 它的草稿

```
镜头表.csv + 项目.csv
        │
        ├─(1) check_cutlist.py            校验，报错就别往下走
        ├─(2) probe.py                    拿到每个素材的真实时长/分辨率
        ├─(3) preflight.py                环境能不能跑（ffmpeg/滤镜/字体/磁盘）
        │
        ├─(4a) render.py                  直接出 mp4  → 交付 / 抖音草稿箱
        └─(4b) export_jianying_spec.py    → spec.json → 剪映草稿（可再编辑）
                                              │
                                              └─ 在 jianying-editor-skill-11.5 里：
                                                 jianying.py build spec.json
                                                 （它调本机 videoeditor.dll 写原生加密草稿）
```

`spec.json` 的字段是对方定的，只有六样：

```json
{"name": "...", "material_dir": "...", "width": 1080, "height": 1920, "fps": 30,
 "video": [{"path": "clip.mp4", "source_start": 1.0, "start": 0.0, "duration": 3.0}],
 "audio": [],
 "text":  [{"text": "标题", "start": 0, "duration": 3, "size": 9, "x": 0, "y": -0.55}]}
```

**表达不了的六样**（`export_jianying_spec.py` 会逐条写进 `<spec>.notes.md`，不静默丢）：
变速、转场、推近/局部放大等运镜、音效轨、原声压低曲线、BGM。
这六样恰恰是我们自己的 ffmpeg 管线的强项——所以正确分工是：

- **要可再编辑** → 走剪映草稿（接受六样损失，人在剪映里补）
- **要直接发出去** → 走 `render.py`（六样全在，但没有可视化时间线可拖）

## 四、如果你要在自己机器上跑它（我们不做，但这几步是必须的）

1. 备份 `E:\JianyingPro Drafts`（它会读写草稿目录和首页索引）。
2. 它的预检默认找 `%LOCALAPPDATA%\JianyingPro\Apps\<版本>\videoeditor.dll`；
   你的剪映装在 `E:\JianyingPro\11.5.0.14471\`，所以要改它的版本路径常量，
   或在该目录下建 junction 指向 E 盘。**没有 fallback，不改就必然 `[!]`**。
3. 依赖 11 个包（uiautomation/playwright/pynput/opencv…），用独立 venv，别装进系统 Python。
4. 先只跑 `build` 出一个 12 秒测试草稿，人工在剪映里打开确认，再谈批量。
5. 它是单人维护的 11 星仓库——把"它坏了怎么办"写进你的流程：坏了就退回 `render.py`，
   我们的成品路径不依赖它。

## 五、一句话

**自动化该停在"产物可被专业工具打开"这一步，而不是"跳过专业工具"。**
它把这句话做成了架构，我们把这句做成了分工。
